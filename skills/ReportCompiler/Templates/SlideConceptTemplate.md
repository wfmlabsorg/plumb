# Slide Concept Template

## Purpose

This template converts report content into slide concepts for building a consultant presentation deck. Each slide concept provides enough detail for Ted or a designer to create the actual slides.

---

## Slide Concept Structure

```markdown
## Slide [#]: [Title]

**Type:** [Title / Section Divider / Content / Data / Comparison / Summary / Visual]
**Source:** [Which report section this comes from]

### Key Message
[One sentence: what should the audience remember after seeing this slide?]

### Headline
[Proposed headline text - should be a complete thought, not just a label]

### Content Elements

**Body Points:**
- [Point 1]
- [Point 2]
- [Point 3]

**Supporting Data:**
- [Key number/stat to include]
- [Another data point]

### Visual Suggestion

[VISUAL: Description of recommended chart, diagram, or image]

**Visual Type:** [Bar chart / Line graph / Pie chart / Process diagram / Comparison table / Icon grid / etc.]
**Data Source:** [Where the data comes from]
**Key Callout:** [What to emphasize visually]

### Speaker Notes

[What Ted should say when presenting this slide. Include:]
- Opening statement
- Key talking points (2-3)
- Transition to next slide
- Anticipated questions and answers

### Design Notes

- [Color/emphasis suggestions]
- [Animation considerations]
- [Layout preferences]
```

## Standard Deck Structure

A typical maturity assessment deck follows this flow:

### Opening (3-4 slides)
1. **Title Slide** — Client name, assessment title, date, presenter
2. **Agenda** — What we'll cover
3. **Executive Summary** — Overall score and key takeaways
4. **Methodology** — How we assessed (brief)

### Assessment Findings (2-3 slides per area)
5-N. **Assessment Sections** — One per major finding area
   - Summary slide with score
   - Key findings detail
   - Gap analysis visual

### Recommendations (1-2 slides each)
N+1. **Recommendations Overview** — All recommendations with priority
N+2 onwards. **Individual Recommendations** — Detail for each

### Closing (2-3 slides)
- **Implementation Roadmap** — Phased timeline
- **Next Steps** — Immediate actions
- **Discussion / Q&A** — Open for questions

## Slide Type Guidelines

### Title Slide
- Client logo placement
- Clean, professional
- Date and presenter name
- No busy graphics

### Section Divider
- Just the section name
- Maybe a subtle icon
- Sets up the next content block

### Content Slide
- Max 4-5 bullet points
- Each bullet: one line if possible
- Leave room for visual element

### Data Slide
- One key chart per slide
- Clear axis labels
- Highlight the key insight
- Source citation

### Comparison Slide
- Side-by-side or before/after
- Clear visual distinction
- Callout the difference

### Summary Slide
- Key takeaways only
- Usually 3-5 points
- Sets up next section

## Visual Type Recommendations

| Data Type | Recommended Visual |
|-----------|-------------------|
| Scores across areas | Radar chart or bar chart |
| Current vs. target | Gap bar chart or thermometer |
| Trend over time | Line chart |
| Composition/breakdown | Pie chart or stacked bar |
| Process flow | Flowchart or swim lane |
| Comparison | Side-by-side table or icons |
| Timeline/roadmap | Gantt chart or milestone diagram |
| Maturity level | Stair-step diagram |

## Speaker Notes Guidelines

Good speaker notes include:

1. **Opening hook** — First thing to say when slide appears
2. **Key points** — What to emphasize (beyond what's on slide)
3. **Evidence/stories** — Supporting details to share verbally
4. **Transition** — How to move to next slide
5. **Q&A prep** — Likely questions and responses

Example:
```
[Opening]
"This brings us to what I consider the most critical finding..."

[Key Points]
- Emphasize the 38% number - this surprised even the client
- Connect this to the forecasting accuracy issues mentioned earlier
- Note that this is solvable with existing technology

[Story]
Share the anecdote from the WFM team lead about "calls appearing from nowhere"

[Transition]
"This data visibility issue feeds directly into our first recommendation..."

[Q&A]
Q: How did you calculate the 38%?
A: Call routing analysis comparing IVR intent vs. final queue landing
```
